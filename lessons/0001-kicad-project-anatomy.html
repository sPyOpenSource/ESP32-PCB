Lesson 1 KiCad Project Anatomy

Your win for this lesson: You can look at any KiCad project folder and name each file's role — so you can modify an existing project without accidentally severing the link between schematic and board.

A KiCad project is not a single document. It is a folder of files. The three most important ones are:

The three core files

.kicad_pro — Project settings

JSON file. Stores project-level configuration: design rules, netclasses, ERC severities, sheet paths, library tables, and which schematic file is the top-level sheet. Your 1CHmotordriver/esp32_mine.kicad_pro is 733 lines of this. You rarely edit it by hand; KiCad manages it.

.kicad_sch — Schematic

S-expression text file. Contains symbols, wires, labels, junctions, and symbol properties (Reference, Value, Footprint, Datasheet). This is the logical design — what connects to what. Your esp32_mine.kicad_sch starts with (kicad_sch (version 20260306) (generator "eeschema").

.kicad_pcb — Board layout

S-expression text file. Contains footprints placed on the board, tracks, vias, zones (copper pours), layers, and the stackup. This is the physical design — where things actually go. Your esp32_mine.kicad_pcb starts with (kicad_pcb (version 20260206) (generator "pcbnew").

Supporting files you will see

.bak / .kicad_pcb-bakAutomatic backup copies KiCad makes when you save. Your repo has several — they are safe to ignore or delete once you are happy with a version.
.netNetlist: the intermediate file Eeschema exports and Pcbnew imports to synchronize schematic changes to the board.
.lib / .dcmSymbol or footprint library and its documentation. Your klepcontroller-rescue.lib is an example.
.gts, .gtl, .gbl, .gbo, .gm1, .drlGerber and drill files — fabrication output sent to the PCB manufacturer.
.pos, .csvPosition (pick-and-place) files for assembly.
.step3D model of the board for mechanical checking.

The invisible link: UUID

Each schematic sheet has a UUID. In your .kicad_pro, the top-level sheet is recorded like this:

"top_level_sheets": [
  {
    "filename": "esp32_mine.kicad_sch",
    "name": "esp32_mine",
    "uuid": "b64a79a8-4f4a-4acb-9115-e844dceb0e9d"
  }
]

That UUID appears in both the .kicad_sch and the .kicad_pcb. It is what keeps schematic and board in sync. If you rename or move files outside KiCad, you can break this link.

Safe modification workflow

  1. Work on a copy. Duplicate the project folder before changing anything. Your .bak files show KiCad already does this automatically — make it deliberate.
  2. Open in KiCad. Open the .kicad_pro file; KiCad loads the schematic and board together.
  3. Edit the schematic first (add/change symbols, wires, footprints).
  4. Export the netlist from Eeschema and import it in Pcbnew to push changes to the board.
  5. Run ERC (Electrical Rules Check) in the schematic and DRC (Design Rules Check) in the board. Fix errors before fabricating.
  6. Generate Gerbers only after DRC is clean.
